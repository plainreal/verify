Verify a record

A record is one signed JSON file covering a single consequential step in an AI agent workflow: a model decision, a tool call, or a human approval. It says what happened and who is accountable for it. A PlainReal deployment writes one for every such step.

This page checks that a record has not been altered since it was signed. It runs the check inside your browser. No PlainReal service is contacted. Nothing you paste leaves this page.

      The record

      Check it yourself. Every assertion behind this page is in this page: canonicalization vectors, hash known-answer tests, signature cases including malleability and non-canonical keys, and the curve algebra. Nothing is downloaded and nothing is fetched. Press the button and they run here, against the same code that just checked your record.

      The key. One public key is embedded here: the demo key that signed the samples. Customer records are signed by the key that deployment holds, so this page cannot check them, and says so instead of showing a failure.

      Your own records. This page holds only the demo key, so it cannot check them. A standalone plainreal-verify CLI takes any public key, needs no PlainReal service, account or key of ours, and contacts nothing, but is not published yet.

      What this does not check. This checks one record: whether its bytes are what was signed. Records reference the records they came from. Following those references, and confirming that a parent really is the one that was cited, is a different check that this page does not perform. Verifying ten records here proves ten records, one at a time. It does not prove the workflow that produced them.

      The cryptography here was written for this page, not copied from a library, so that the whole thing is one readable file. It is checked against Go's implementation and against your own browser's WebCrypto where that supports Ed25519. Details are in the repository.

      Your data. Whatever you paste stays in this tab. There is no code here that could transmit, store, cache or log it. Close the tab and it is gone.

      Where this came from. github.com/plainreal/verify carries the source, the security policy, and each release's SHA-256 inside a signed tag, so you can check the copy you were handed against a key rather than against our word. Opening it needs the network. This page still asks for nothing.

      Who maintains this. PlainReal, at plainreal.com. That site describes the product and makes claims about it; this page makes only the one it can compute in front of you. Where the two ever disagree about what a signature proves, this page is the one that has to be right.
